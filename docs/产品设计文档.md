## 1. 产品定位与形态（一句话版）

面向高校的 AI 原生人才培养平台：**岗位能力模型为地基，陪练官对话为体验核心，证据链评价为出口**。Demo 形态 = 移动端候选人 H5（文档表述为 APP）+ 教师端管理后台（PC），同一部署两个入口、共享数据层。学生 100% 是体验主角；教师以"必修课配置人"轻量在场；企业以"真题出处"隐身在场。

## 2. 标准层 · 能力模型体系（地基）

- **软硬四模块**：硬技能（知识/技能——决定下限，测验与演练考核）+ 软技能（胜任力/经历——决定上限，行为锚点与证据考核）。考核逻辑与培训方式双重分离。
- **三层复用架构**：【通】GEN 全岗位通用 →【职】FPM 职能共享 →【岗】GPM 岗位定制（1-2 项）。新岗位 = 三池组装，词典是基座。
- **编码体系**（唯一 ID，入库规范首列）：`CMO-01-沟通表达`（胜任力）/ `GEN-AI技术知识` / `FPM-产品方法知识` / `GPM-评测集设计技能`；子级：知识点 `.K序号`、任务场景 `.T序号`、关键行为 `.L级.B序号`、岗位模型 `PM-01~10`。
- **三本词典**：胜任力 12 条×4 级×6 行为=288 条（一根成长轴+构面降为标签）；知识 6 域 35 知识点（二值掌握，无题不成点）；技能 6 项×12 任务场景（四级成长轴，无任务不成技能）。
- **等级制度**：胜任力/技能用四级（入门/了解/熟练/精通）；知识用二值+域级聚合（布鲁姆层级映射题目难度）。**分数给区间不给假精确**。
- **建模前提**（文档须体现）：理想化假设词典已大量企业验证（类比行业头部测评平台地位）；运营大后台内容组装优先于二次开发；企业定制/同名不同级等问题在该前提下暂不处理。

## 5. M3 首测诊断（陪练官对话 + 评分工作流）★当前模块

### 5.1 架构：主 Agent 与评分工作流分离（三个理由）

1. **安全（最小知识原则）**：主 Agent 的 prompt 不含任何评分逻辑——用户反向打探时它"不是忍住不说，是真的不知道"，架构级防套话，优于提示词级约束。
2. **目标函数冲突**：测评=最大化信息增益（挖透缺点）；陪练=最大化成长（鼓励推进）。两种反向 persona 塞一个 prompt 必然语气漂移。
3. **工作流优于子 Agent**：评分是确定性管线（语料→JSON）而非自主探索；独立部署/测试/迭代，多维度可并行。

```
候选人 ⇄ 主Agent(陪练官：对话/追问/挡话) ──对话语料──▶ 评分工作流(独立prompt)
                                                        证据抽取→词典锚点匹配→聚合
                   ◀──结构化JSON(分数区间/置信度/证据/缺口)──┘
前端报告页消费 JSON（报告模板属产品层，教师端将来消费同一结构）
```

### 5.2 对话设计

- **开场白**（用户指定）："很荣幸能跟你接下来一起共事。在我们开始之前，想先对你做一个简单的了解——我们花个 3~5 分钟聊一聊，看看你现在的一个能力情况。"
- **身份**：陪练官，**不是虚拟面试官**——共事伙伴口吻，不是考官。不用简历解析（学生无简历概念），对话即摸底、即语料采集。
- **话题框架**（5 个，按序推进，每话题映射词典维度 ID）：

| # | 话题 | 考察维度 |
|---|---|---|
| 1 | AI 协作经历 | CMO-06 学习敏锐度 / GEN-AI应用技能 |
| 2 | 困难决定 | CMO-09 抗压与坚韧 / CMO-02 结构化思维 |
| 3 | 学习方式 | CMO-06 学习敏锐度 |
| 4 | 岗位认知 | CMO-02 结构化思维 |
| 5 | 团队协作 | CMO-03 跨职能协作 / CMO-01 沟通表达 |

- **滚动评估**（真 AI 模式）：每 2 轮静默调用评分工作流，将"证据缺口维度"回注主 Agent 引导自然补充——实现"不机械走流程"。
- **追问上限**：单话题追问 ≤1 次（2026-08-22 用户调整，原 3 次），服务端计数器控制。
- **外挂总轮次断路器（2026-08-22 用户指定）**：总对话轮次（主干+追问）≤3 轮——实现为 API 边界的外挂规则，第 3 轮回复后自动追加收尾语并标记可结束，**不修改 Agent 的 system prompt 与话题/追问内部逻辑**（与演示分支选择器同一"外挂"设计哲学：产品规则外置于 Agent 之外）。
- **结束条件**：话题走完 / 用户主动结束（可确认弹窗）/ 累计轮次上限。

### 5.3 意图识别规则（用户点名记录）

| 意图 | 识别规则（正则） | 处理策略 |
|---|---|---|
| 打探评分 | /评分\|打分\|标准\|怎么评\|几分\|权重\|维度有哪些\|胜任力是什么/ | **标准挡话术**："评分的细节我卖个关子，完整维度会在结束后的成长报告里呈现" + 继续当前话题；不泄露任何评分内容 |
| 疲惫想停 | /累了\|不想聊\|休息\|改天\|算了\|结束吧/ | 友好收尾，提示可点"结束初聊"看报告；不勉强 |
| 拒答/不知道 | /^(嗯\|哦\|好\|行\|是的\|对\|不知道\|没想过\|不清楚\|没啥)[。.!！~]?$/ | 不逼问、不计负分；换个问法或直接换话题 |
| 过短回答 | <6 字且无疑问号 | 请对方展开（"具体点，当时情况、你做了什么"），仍短则按追问计数推进 |
| 正常回答 | 其余 | 确认回应（引用其回答片段）+ 下一追问 |

真 AI 模式下意图处理写入主 Agent system prompt（第 3 条原则），虚拟模式为上表规则版实现。

### 5.4 评分工作流

- **输入**：对话语料（候选人发言切片）。
- **输出 JSON Schema**：
```json
{ "dimensions": [{ "dictId": "CMO-01", "name": "沟通表达", "scoreRange": [1,2], "confidence": "mid", "evidence": ["对话原话"] }],
  "profile": "总体画像两三句", "improve": [{ "dictId": "CMO-02", "direction": "一句话建议" }] }
```
- **规则**：分数=区间（1-4 级制）；confidence=high/mid/low（语料不足必须 low，报告页显示"待任务验证"）；evidence 必须引用候选人原话（评分可追溯=证据链立场）；只评候选人的话。
- **锚点**：评分 prompt 锁定维度白名单（当前 6 维：CMO-01/02/03/06/09 + GEN-AI应用技能），对应词典 ID。
- **双模式**：虚拟=启发式（词典关键词命中率+语料丰富度→区间分，确定性可演示）；真 AI=独立 prompt 调 LLM，失败自动降级虚拟数据并标注。
- **已知待补**：评语文本目前为模型直出，**未接专业报告语料库**——待用户提供评语样例/培养建议写法后，以 few-shot 注入评分 prompt（轻量 RAG），生产期切真 RAG。

### 5.6 百分位算法与常模说明（2026-08-22 用户定）

- **算法**：原始分 = 等级映射 0-1（L1=0、L4=1，区间取中值）→ 标准分 z = (原始分 − μ) / σ → 百分位 = 正态累积分布 CDF(z) × 100，截断 1-99。
- **常模假设（演示常模）**：学生初学者群体原始分近似正态 N(μ=0.40, σ=0.23)（约等于群体均值 L2.2、标准差 0.7 个等级）。**当前无真实常模数据，此为演示假设参数**；接入真实用户分布后仅替换 μ/σ 两个参数，界面与算法结构不变——即测评行业的常模建设路径，也是数据飞轮的一层。
- **无样本特判（用户指定）**：维度无证据样本（候选人未说话/未触及该维度）→ 百分位强写 **0%**（显示"超过 0% 人群"，等级=待提升）——区分"测了不行"与"根本没测到"的极端场景兜底。
- 等级分档：<30% 待提升，30-70% 中等，>70% 优秀。

## 6.5 课程推荐与分日学习规范（2026-08-23 用户定）

### 核心规则
1. **欠佳即必修**：胜任力（软技能）或知识技能（硬技能）在初聊报告中被认定为"欠佳"（百分位 < 30%）→ 对应课程自动标记"重点学习"，进入必修区。
2. **必修课两部分**：
   - 导师要求：课纲规定必学（教师配置）
   - 系统推荐：系统判定必学（评估驱动），卡片打"系统"标签
3. **每日任务制**：必修区为当天必须完成的内容，不能跨界（防止超前学习/刷题）。想多学 → 走选修。
4. **软硬搭配**：每日课程必须包含至少一个软技能 + 一个硬技能，组合学习，不能只有其中一种。

### 选修课排序
- 上方"建议学习"：与画像相关但未进入必修的课程
- 下方"其他课程"：按兴趣自由探索
- 文案："本部分鼓励学生自主学习，非必须要求。"

### 必修区文案
"本部分课程为每日必须学习的内容，请完成今天的全部内容学习。"
