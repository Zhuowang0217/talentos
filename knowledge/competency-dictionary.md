# TalentOS 胜任力词典库 v1（软技能·12 条）

> 基座文档。结构决策（2026-08-22 用户确认）：**一条胜任力 = 一根成长轴**（行业分级制骨架）；构面降级为关键行为标签（两级结构）；每级关键行为 6 条；importance 不在词典层，属岗位模型属性。
> 语料参照：行业公开胜任力词典规范（KSAO 模型 + 行为描述区分绩优绩平 + 禁用模糊词）及四级体系最佳实践。
> 前提：理想化假设词典已通过大量企业验证（见 research/09 §〇）。

## 等级状态定义（四级，参照 IBM 五级体系裁剪）

| 等级 | 对应 IBM 状态 | 状态描述 |
|---|---|---|
| L1 入门 | 基本理解 | 认识该胜任力的价值与基本要求；在熟悉、低风险情境中按范例行事，需要指导 |
| L2 了解 | 具备工作经验 | 在常规情境中独立应用并产出合格结果；复杂情境仍需支持 |
| L3 熟练 | 具备丰富经验 | 在复杂多变情境中灵活运用，形成个人方法；指导他人 |
| L4 精通 | 深度理解业务 | 在高度复杂、模糊情境中创造性行事；制定标准、影响组织；被他人寻求咨询 |

## CMO-01 沟通表达

**定义**：以清晰、结构化的方式传递信息与观点，准确理解他人意图，并根据对象调整表达策略的能力。
**构面标签**：结构化表达 / 倾听理解 / 向上汇报

### L1 入门
状态：按模板组织信息，在熟悉话题上做简单陈述。
- 用模板撰写周报、会议纪要等常规文档
- 在小组讨论中复述他人观点且不改变原意
- 使用语音、文字、图表中至少一种方式说清一个简单问题
- 在被提问时给出与问题直接相关的回答
- 记录并转达团队内的基础信息
- 识别明显的信息传达偏差并主动澄清

### L2 了解
状态：独立完成常规汇报与讨论，表达有条理。
- 用"结论-依据-建议"结构汇报工作进展
- 在需求评审中讲清一个功能的问题定义与方案要点
- 将算法同学的技术描述转译为业务方可理解的语言
- 会议前准备议程，会后 24 小时内发出结论与待办
- 根据听众（技术/业务/管理层）调整同一内容的详略与措辞
- 通过复述确认自己理解的对方需求与原意一致

### L3 熟练
状态：在复杂议题和多方对话中主导沟通，表达精准有说服力。
- 面对质疑时先界定分歧点再逐点回应，不回避关键问题
- 将一个含糊的业务诉求整理为结构化的问题陈述并获认可
- 在跨职能会议上引导分歧双方聚焦共同目标
- 用数据与案例支撑观点，当场改变相关方的错误预期
- 向管理层汇报坏消息时同步给出应对选项与代价
- 指导他人改进文档与汇报的表达结构

### L4 精通
状态：在高压、高博弈场景中掌控沟通，表达本身成为影响力。
- 在决策会议上用一次陈述统一多方立场并促成决议
- 面向客户高管即兴阐述产品价值并应对深度追问
- 代表团队对外发声，表述被引用为组织级口径
- 为组织制定沟通规范（文档模板、评审规则、汇报标准）
- 识别组织内的沟通结构性障碍并推动机制改进
- 被其他团队邀请辅导关键汇报与谈判

## CMO-02 结构化思维

**定义**：将复杂问题拆解为可处理的组成部分，建立框架与优先级，并保持逻辑一致性的思考能力。
**构面标签**：框架构建 / 逻辑拆解 / 优先级判断

### L1 入门
- 使用现成框架（如 5W2H、SWOT）描述简单问题
- 将一个任务按步骤列出清单并逐项完成
- 区分事实与观点，引用信息时注明来源
- 识别他人论述中明显的逻辑跳跃
- 按给定维度对信息进行分类整理
- 用图表呈现简单数据的对比关系

### L2 了解
- 将模糊需求拆解为 3-5 个可独立验证的子问题
- 为方案建立假设并设计验证顺序
- 在多任务并行时按影响与紧急度排列处理顺序
- 识别方案中的前提条件并逐项检验
- 用同一框架对比多个候选方案得出结论
- 发现数据结论与业务直觉矛盾时先核查口径

### L3 熟练
- 面对全新领域问题时自建分析框架并获得团队认可
- 将跨部门争议还原为结构化的目标冲突与资源约束
- 在信息不完整时识别关键未知项并设计补全路径
- 识别复杂系统中的因果链而非停留在相关关系
- 砍掉看似重要但与目标无关的工作项并说明理由
- 指导他人搭建需求分析与方案设计框架

### L4 精通
- 将组织的重复性问题抽象为可复用的方法论
- 在高度模糊的战略议题上给出清晰的思考路径供决策
- 识别跨团队工作流中的结构性瓶颈并重组流程
- 对他人的复杂方案快速指出逻辑断点与隐藏假设
- 制定组织级的问题分析与决策标准
- 其框架被其他产品线采用为通用方法

## CMO-03 跨职能协作

**定义**：与算法、工程、设计、业务等不同职能角色建立信任、协调分歧、共同交付的能力。
**构面标签**：关系建立 / 冲突处理 / 协同推进

### L1 入门
- 说出协作方职能的基本职责与工作语言
- 按约定时间交付自己负责的协作事项
- 在他人求助时响应并如实说明自身限制
- 参加跨职能会议时遵守议程与角色分工
- 记录协作中的承诺与截止日期并跟踪
- 在流程工具中同步自己的任务状态

### L2 了解
- 主动同步进展变化，不让协作方被动等待信息
- 与算法工程师沟通需求时给出可执行的问题定义
- 识别一次协作冲突的利益根源而非停留在情绪
- 在排期冲突时提出双方均可接受的折中方案
- 明确每次协作的接口人、交付物与验收标准
- 请求他人支持时说明背景、诉求与期限

### L3 熟练
- 在三方以上利益冲突中设计出各方可接受的协作机制
- 推动没有汇报关系的团队完成跨部门交付
- 预判协作风险并在冲突爆发前介入化解
- 在资源被回收时重组协作方案保住关键目标
- 建立跨团队的例会与信息同步机制并运转良好
- 帮助他人调解跨职能矛盾并沉淀处理方法

### L4 精通
- 主导建立组织级的跨部门协作流程与接口标准
- 在重大分歧中促成高层与一线达成一致行动
- 将长期摩擦的团队间关系转化为稳定合作模式
- 代表组织与外部伙伴建立协作框架
- 协作机制被复制到其他项目组
- 被视为跨部门关键项目的当然协调人

## CMO-04 用户同理心

**定义**：理解用户的真实处境、动机与约束，站在用户立场检验产品决策的能力。
**构面标签**：需求洞察 / 体验关注 / 用户立场

### L1 入门
- 完成用户访谈提纲并按提纲执行访谈
- 区分用户陈述的表面诉求与使用场景
- 记录用户操作路径中的困惑点与中断点
- 在方案讨论中引用至少一个真实用户场景
- 使用产品时以新手视角走完全流程
- 收集并归类用户反馈到既定标签体系

### L2 了解
- 从访谈记录中提炼出用户目标与行为模式
- 识别用户"说的"与"做的"之间的差异并求证
- 为功能设计撰写包含用户处境的用户故事
- 主动体验竞品并指出体验差异的具体原因
- 在评审中代表用户立场质疑团队假设
- 将用户反馈转化为可验证的需求假设

### L3 熟练
- 构建分层的用户画像并指导差异化设计决策
- 在数据与用户行为矛盾时设计现场观察求证
- 识别用户未言明的深层动机并转化为产品机会
- 在商业目标与用户价值冲突时给出平衡方案
- 主导可用性测试并将发现落实为迭代项
- 带动团队建立"先看用户再定方案"的讨论习惯

### L4 精通
- 定义组织级的用户研究方法与体验标准
- 从零建立用户洞察体系并影响产品战略方向
- 在重大产品决策中使长期用户价值成为裁决依据
- 识别用户行为背后的社会性/组织性动因并预判演变
- 其用户洞察方法成为团队通用能力
- 被邀请指导其他业务线的用户体系建设

## CMO-05 批判性思维

**定义**：对信息、结论与自身假设保持审视态度，通过求证与多角度分析形成独立判断的能力。
**构面标签**：质疑求证 / 多角度分析 / 结论严谨

### L1 入门
- 对来源不明的信息先查证再使用
- 说出自己结论所依赖的假设
- 列出一个方案的至少两种反面意见
- 区分相关性与因果性的简单案例
- 对"大家都这么做"的惯例提出疑问
- 承认自己不知道的事项而不猜测

### L2 了解
- 对数据结论核查口径、样本与时间范围
- 主动寻找与己方结论相反的证据
- 评估信息来源的立场与利益偏向
- 在方案评审中指出论证的前提脆弱点
- 用小成本实验替代无依据的争论
- 修正自己已公开表达的错误结论

### L3 熟练
- 系统性拆解复杂论证的假设链并逐一定位薄弱环节
- 在群体意见一致时构建反方论证检验决策
- 识别数据偏差的来源（幸存者、选择、度量）
- 对权威结论还原其适用条件与边界
- 设计交叉验证方案确认关键判断
- 帮助他人识别推理漏洞而不引发防御

### L4 精通
- 在组织决策文化中植入质疑与求证机制
- 对行业共识提出被后续验证的质疑
- 在重大不确定决策中设计系统性验证路径
- 识别组织集体盲点并推动认知升级
- 制定批判性分析的标准与评审纪律
- 被邀请对关键决策做独立审视

## CMO-06 学习敏锐度

**定义**：快速获取新知识、在陌生领域中迁移已有经验、从反馈中持续改进的能力。
**构面标签**：新知获取 / 迁移应用 / 反思迭代

### L1 入门
- 列出自己的知识盲区清单并安排学习
- 使用文档、课程、社区等至少三种渠道自学
- 复述新学概念的定义并举出例子
- 在指导下完成陌生工具的首次使用
- 记录学习中的疑问并主动求解
- 按计划完成一个学习任务

### L2 了解
- 在限定时间内自学新技术并产出摘要供他人使用
- 将既有方法论迁移到新问题上并调整适配
- 向内行提出有质量的问题而非泛泛请教
- 从失败任务中总结出可执行的改变项
- 跟踪领域动态并定期输出要点
- 在新环境中快速识别需要掌握的关键知识

### L3 熟练
- 在全新领域两周内形成可指导决策的理解框架
- 教授他人自己刚掌握的知识并讲透原理
- 从跨领域案例中提炼可迁移的规律
- 主动构建个人知识体系并持续修剪
- 面对否定性反馈提取有效成分并快速调整
- 为团队建立新技术的学习路径

### L4 精通
- 在技术范式转换期领先组织完成认知升级并输出地图
- 从零掌握陌生领域并达到与专家对话水平
- 将学习机制产品化为团队流程（复盘、共学、灯塔）
- 识别组织的学习结构性障碍并改造
- 其学习方法被广泛效仿
- 被视为组织内"学什么问谁"的终极节点

## CMO-07 创新与开放

**定义**：对新事物保持好奇与接纳，探索非常规解法，并将创意推进为可落地方案的能力。
**构面标签**：好奇探索 / 拥抱变化 / 创意落地

### L1 入门
- 试用新工具并分享使用体验
- 在常规做法之外提出至少一个备选思路
- 面对流程变化按要求快速调整操作
- 收集其他行业的同类问题解法
- 参加创新讨论并贡献想法
- 记录突发的灵感并定期回顾

### L2 了解
- 提出对现有流程的改进建议并亲自试点
- 将其他领域的方法引入当前问题
- 在方案受限时提出绕开限制的新路径
- 主动验证新想法的最小可行版本
- 对失败实验做归因并保留可复用发现
- 支持并协助他人试验新想法

### L3 熟练
- 主导从 0 到 1 的新方案设计并推动落地
- 在资源约束下用重构问题的方式创造解空间
- 识别组织内扼杀创新的机制并提出修正
- 将多个来源的碎片想法组合成新方案
- 为创新争取试点空间并管理失败风险
- 辅导他人把模糊创意变成可评审方案

### L4 精通
- 定义组织级的创新机制（创意管道、容错预算）
- 开辟被验证成功的新产品方向或品类
- 在市场范式转换中带领组织抢先转身
- 其创新方法论被其他团队复用
- 识别长期性的结构性机会并持续布局
- 被邀请出任新方向的探索负责人

## CMO-08 影响与推动

**定义**：在没有正式授权的情况下，通过论证、关系与机制推动他人支持并共同行动的能力。
**构面标签**：无授权影响 / 资源争取 / 共识建立

### L1 入门
- 明确说出自己推进事项需要谁的支持
- 向支持者清晰陈述请求事项与理由
- 按承诺向相关方同步进展
- 在授权范围内自主推进并汇报结果
- 识别阻碍推进的具体环节并上报
- 完成被分配的推动型任务（催办、跟单）

### L2 了解
- 用数据与案例说服同事支持非强制事项
- 找到关键决策人并以对方关心的语言陈述
- 在被拒绝后调整策略再次争取
- 组织小型协调会推动跨岗位事项
- 将大目标拆为他人可轻易承诺的小步骤
- 跟踪承诺直到闭环并公开结果

### L3 熟练
- 在无授权情况下推动多团队联合行动并达成目标
- 识别组织的非正式权力结构并有效借力
- 通过预沟通在正式决策前锁定关键支持
- 设计利益交换方案化解推进阻力
- 在争议中构建多数共识并留出异议空间
- 带动他人主动认领推动任务

### L4 精通
- 推动组织级战略项目跨越部门壁垒落地
- 在无先例、无授权、有反对的情况下促成关键合作
- 建立让横向推动常态化的组织机制
- 其倡议获得高层背书成为正式项目
- 影响力跨越组织边界（客户、伙伴、行业）
- 被视为组织内重大事项的推动枢纽

## CMO-09 抗压与坚韧

**定义**：在高压、挫折与不确定性中保持稳定输出与情绪调节，持续逼近目标的能力。
**构面标签**：压力承受 / 结果导向 / 情绪调节

### L1 入门
- 在截止期压力下按计划完成任务
- 面对批评时先听完再回应，不即时对抗
- 说出自己的压力信号并采取一种调节方式
- 任务受阻时及时求助而不是隐瞒
- 记录延误并说明原因与补救
- 保持基础工作节奏不因情绪中断

### L2 了解
- 在多任务高压下重排优先级保住关键交付
- 方案被否后当天给出修订版本
- 面对不合理指责时用事实回应并维护关系
- 在需求反复变更时管理自己的挫败感并适配
- 识别长期压力源并提出调整建议
- 在团队低气压时保持稳定输出

### L3 熟练
- 在项目重大受挫（上线失败/数据事故）后主导恢复
- 持续数月推动艰难目标不松劲并阶段性兑现
- 在多方施压的冲突要求中保持判断独立
- 帮助团队成员度过高压期并恢复产出
- 将压力转化为流程改进的输入
- 在不确定中为团队提供稳定预期

### L4 精通
- 在组织危机中成为稳定军心的关键角色
- 长周期战略任务顶住反复质疑持续兑现
- 建设团队级的韧性机制（复盘、轮休、心理安全）
- 在极限约束下带领团队完成不可能交付
- 其沉着应对成为组织案例
- 高压情境中被赋予最关键的谈判与恢复任务

## CMO-10 责任担当

**定义**：对结果负责到底的 ownership，主动补位、敢于决策、闭环交付的行为倾向。
**构面标签**：主动补位 / 闭环意识 / 敢于决策

### L1 入门
- 承诺的事项按时交付或提前预警
- 出错时第一时间承认并说明影响
- 完成任务后主动确认验收结果
- 发现明显问题即使不属自己职责也提醒相关人
- 保存关键决策与交付的记录
- 不将责任推给流程或他人

### L2 了解
- 对自己模块的端到端结果负责（含他人接口问题）
- 在职责边界模糊时主动认领并推进
- 出现事故时先止损再复盘归因
- 对低风险事项独立决策并承担后果
- 跟踪自己发起的事项直至业务效果确认
- 公开复盘自己的失误并输出改进项

### L3 熟练
- 为跨团队结果主动承担最终责任
- 在无人指派时发起并完成组织需要的关键任务
- 在高风险决策中权衡后拍板并对结果负责
- 建立事项的闭环机制（发起-跟踪-验收-复盘）
- 掩护团队失误后私下辅导而非公开追责
- 其负责的事项被默认为"放心线"

### L4 精通
- 承担组织级失败并主导走出困境
- 在战略分歧中为长期正确的事项担责压阵
- 塑造组织的责任文化（补位、闭环、复盘成为默认）
- 为他人担当使其敢于冒险创新
- 建立授权与问责平衡的机制
- 被委以组织最不能失败的任务

## CMO-11 伦理与合规意识

**定义**：识别技术与应用中的伦理风险、数据隐私与合规边界，并主动设计防护的能力。
**构面标签**：风险识别 / 隐私保护 / 责任边界

### L1 入门
- 说出数据采集与使用的基本合规要求
- 在方案中使用数据前确认授权范围
- 识别明显的隐私泄露场景并上报
- 了解 AI 生成内容的标识要求
- 引用他人内容时注明来源
- 参加合规培训并完成测验

### L2 了解
- 在方案评审中主动列出生成内容的误用风险
- 识别训练/评测数据的版权与授权问题
- 设计数据脱敏方案并核查执行
- 识别算法输出的偏见案例并提出修正
- 界定 AI 建议的适用场景与免责说明
- 跟踪法规更新并同步团队

### L3 熟练
- 主导产品的合规风险评估并制定分级策略
- 在商业压力与合规冲突时坚持边界并给出替代方案
- 设计人工复核机制拦截高风险输出
- 建立数据全生命周期的管控流程
- 处理一次合规事件并沉淀预防机制
- 辅导团队将伦理检查纳入设计默认步骤

### L4 精通
- 制定组织级的 AI 伦理与合规框架
- 代表组织参与行业标准与监管对话
- 在产品战略层面前置合规架构设计
- 识别尚未立法的前沿风险并提前布防
- 其合规框架成为行业参照
- 被监管方或客户信任为合规裁决人

## CMO-12 商业敏感

**定义**：理解产品所处的商业模式与成本结构，将技术选择与设计决策换算为商业价值的能力。
**构面标签**：价值判断 / 成本意识 / 市场感知

### L1 入门
- 说出自己产品的收费模式与目标客户
- 了解一个功能的主要成本构成
- 记录竞品的定价与版本策略
- 区分收入、成本、利润的基本关系
- 关注行业新闻并标注与己有关的部分
- 在讨论中询问"这个功能谁付钱"

### L2 了解
- 估算一个 AI 功能的 token/推理成本并纳入方案
- 用商业价值（留存、转化、客单）论证需求优先级
- 分析一个竞品动作背后的商业意图
- 识别免费与收费功能的边界设计逻辑
- 在方案中比较自建与采购的成本差异
- 跟踪单位经济模型的关键指标

### L3 熟练
- 构建产品的单位经济模型并指导定价决策
- 在技术方案评审中量化成本-收益权衡
- 识别新的商业化机会并设计验证实验
- 预判市场变化对产品结构的影响并提前调整
- 与销售/客户直接对话校准价值假设
- 带动团队用商业语言讨论技术取舍

### L4 精通
- 主导产品商业化战略并落地为收入结果
- 设计被市场验证的定价与打包模式
- 在行业周期变化中调整商业结构保全增长
- 识别第二曲线并完成 0 到 1 的商业化
- 其商业判断成为组织定价与投资依据
- 代表组织对外阐述商业逻辑

## 附一：结构对照与出处（2026-08-22 补，参照《过去预测未来：行为面试法》）

行业行为面试体系的三层条目结构，与本词典的映射：

| 行业三层 | 本词典对应 | 说明 |
|---|---|---|
| 定义（学术性一句话） | 定义 | 两者同源同风格 |
| 操作定义（5-6 条行为描述，不分级） | 四级"状态 + 关键行为" | 我们更强：分级即 BEI 编码词典思路（HayGroup 胜任力词典 = 定义 + 行为指标，编码时计次数与等级——本书第二章原文佐证），一根成长轴由此成立 |
| 行为面试题目（激发行为的问题） | **待补：行为激发问题层** | 每条胜任力配 3-5 个"请描述一次你…"式问题，作为 Agent 导师追问语料与沙盘情境设计原料（toolkit 的核心部件） |

**行为写法裁定**：本词典维持"动词开头、可观察、无模糊词"的写法（行业最佳实践 + AI 查表需要）。书中操作定义含较多特质化表述（"值得信赖""好奇心强"），作为定义层参考，不替代行为层。

## 附二：词典 → 岗位模型 组装规则

1. 岗位模型 = 从词典选择条目 + 为每条设定**目标等级（L1-L4）与 importance（高/中/低）**——importance 在此层，不在词典层（2026-08-22 用户修正）
2. 学生类岗位建议选择 8-12 条；AI 产品经理（企业服务方向）岗位模型另文档定义
3. 新岗位建模优先复用词典条目；不够时新条目须走"AI 生成四级初稿 → 人审定稿"流程入库（运营在大后台完成，用户不感知细节——对话式推荐，2026-08-22 用户确认）
4. 构面标签用于行为检索、报告聚类；不作为结构层级
5. 每条胜任力的 toolkit 须含**行为激发问题**（3-5 个，"请描述一次你…"式，参照行为面试题目设计）——供 AI 导师追问与沙盘情境生成使用
